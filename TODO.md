- [x] **Responsive DARKODE shell and navigation** — Build a polished dark black/charcoal interface branded DARKODE with the subtitle `PRIVATE // MEMBERS ONLY`; provide a persistent top navigation bar with search, fictional user menu, `Messages 3`, `Alerts 2`, and online status; provide a desktop left navigation with Dashboard, Forums, Members, Private Messages, Notifications, Bookmarks, Reputation, Settings plus forum categories; provide contextual right widgets for online members, recent activity, trending threads, unread messages, forum statistics, and user reputation; on mobile collapse the left sidebar into a hamburger menu, move right widgets below the main content, and keep the top navigation compact.
- [x] **Forum browsing and thread experiences** — Create dashboard, forum index, category thread lists, and individual thread pages; include the requested fictional categories, thread titles, realistic fictional author/category/reply/view/last-reply/timestamp metadata, pinned/locked/unread/bookmarked/subscribed states, breadcrumbs, sorting/filtering/pagination controls, classic post layouts, quote/reply/bookmark/report actions, reputation and badges beneath authors, and safe syntax-highlighted code blocks; do not add CTF challenges or unsafe criminal content.

- [x] **Search and bookmarks** — Search thread titles, post content, usernames, categories, and tags; show result counts and result metadata; provide category/author/date/replies/popularity filters; allow bookmarking threads, listing the example bookmarks, and removing bookmarks with useful empty states.
- [x] **Settings and local persistence** — Provide Account, Appearance, Notifications, and Privacy settings with the requested fields and controls; use local application state/localStorage to persist username, rank, reputation, bookmarks, notifications, messages, read threads, preferences, online state, and badges across refreshes; ship populated demo data immediately.

- [x] **Validation and checkpoint** — Register diagnostics before application code, run the production build, verify preview readiness and the route manifest, resolve actionable diagnostics, confirm all content is fictional and local-only, and checkpoint the final implementation to the canonical repository without enabling publication.
